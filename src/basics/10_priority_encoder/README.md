# 10 · 8:3 优先编码器 priority_encoder

把 8 位请求里**优先级最高**的那个 1 编码成 3 位索引，`valid` 标志是否有请求。

## 这一课学什么
- 编码器 = 译码器的逆：one-hot/多热 → 二进制索引
- “优先级”解决多个请求同时为 1 的歧义（这里取最高位优先）
- `casez`/`if-else` 链表达优先级；全 0 输入时 `valid=0`

> 软件类比：像 `for (i=7; i>=0; i--) if (req[i]) return i;` 的“返回第一个命中”。但硬件里这是一坨**并行**的优先级网络，一拍出结果，不是循环。

## 运行
```bash
make        # 穷举 256 种输入，对照行为模型自校验 [PASS]
make wave
make clean
```

## 上板玩法
- 多个按键/中断源接 8 位请求，编码出“当前该服务谁”，是中断控制器的核心。

## 动手改
1. 改成**最低位优先**，对比仲裁顺序差异。
2. 输出改成 one-hot 的 grant（只保留最高优先那一位），就接近 `advanced/18_prio_arbiter`。

## 对应真实开源项目
- 优先级仲裁广泛用于中断控制器；可对照本仓 `advanced/18_prio_arbiter` 与各类 RISC-V SoC 的 PLIC。
